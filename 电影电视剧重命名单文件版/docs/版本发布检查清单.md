# 版本发布检查清单

每次发布新版本（如 1.3.0 → 1.4.0）前，按顺序完成以下检查。**自动验证**步骤可运行 `scripts/check_release.py` 一键执行。

## 一、版本号（core/version.py 唯一来源）

- [ ] 确认变更类型决定版本段位：
  - MAJOR（如 2.0.0）：不兼容的架构/行为变更
  - MINOR（如 1.4.0）：向后兼容的新功能
  - PATCH（如 1.3.1）：向后兼容的缺陷修复
- [ ] `core/version.py` 中 `__version__` 已更新
- [ ] `RELEASE_DATE` 已更新为发布日期

## 二、Changelog（CHANGELOG.md，Keep a Changelog）

- [ ] 将 [Unreleased] 内容按分类整理（新增/改进/废弃/移除/修复/安全）
- [ ] 创建新版本区块：`## [x.y.z] - YYYY-MM-DD`，移除 Unreleased 标记
- [ ] 每个变更条目描述**对用户可观察**的影响（不是代码内部细节）
- [ ] 底部版本链接已添加（`[x.y.z]: <compare 链接>`）

## 三、自动验证（scripts/check_release.py）

- [ ] 运行 `python3 scripts/check_release.py`：
  - version.py 与 CHANGELOG 最新版本一致
  - CHANGELOG 含全部六个变更分类且格式合法
  - git 无未提交改动（可选项 `--check-git`）
- [ ] 运行 `python3 scripts/check_release.py --run-tests`：全功能测试 6/6 通过

## 四、功能回归

- [ ] 全功能测试：`python3 tests/test_all_features.py`（6/6）
- [ ] 核心引擎测试：`PYTHONPATH=. python3 tests/test_media_renamer.py`
- [ ] GUI 冒烟：`QT_QPA_PLATFORM=offscreen` 启动主窗口无异常
- [ ] 涉及解析引擎变更时：16 个典型文件名用例全部正确

## 五、发布（GitHub）

- [ ] 提交并推送：`git add -A && git commit && git push`
- [ ] 打标签：`git tag v<版本号>` 并推送 `git push --tags`
- [ ] 创建 Release：`gh release create v<版本号> --title "..." --notes "..."`（从 CHANGELOG 提取变更摘要）
- [ ] 验证 Release 页面可见、CI 绿

## 发布后

- [ ] 在 CHANGELOG.md 新建空的 [Unreleased] 区块
- [ ] 如发现紧急问题，按 PATCH 段位发布补丁版
