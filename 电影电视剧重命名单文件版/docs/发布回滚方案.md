# 发布回滚方案

> 适用：影视文件智能重命名工具（tv-media-renamer）发布后的异常处置。
> 原则：**先止血（让用户可用），再定位根因，最后恢复流程。**

---

## 1. 什么情况需要回滚

| 级别 | 现象 | 处置 |
|---|---|---|
| P0 严重 | 新版本启动崩溃 / 批量重命名破坏文件（数据损失风险） | **立即回滚** |
| P1 功能 | 主要功能不可用（解析、扫描、重命名异常），用户无法完成核心操作 | 尽快回滚 |
| P2 轻微 | 个别格式解析偏差 / UI 问题，核心流程可用 | 优先修复发布补丁（PATCH） |

**判断依据**：发布后 24 小时内收到多个同类反馈、或 CI 冒烟未覆盖的崩溃（如特定系统/文件路径）。

---

## 2. 回滚操作（GitHub 层面）

### 2.1 回滚 Release（用户不可再下载到坏版本）

```bash
# 1) 删除损坏的 Release（保留 tag 或同时删除）
gh release delete v1.4.0 --repo 1525745393/tv-media-renamer --yes

# 2) 若也要移除 tag（不推荐，会丢失历史；通常保留 tag 供排查）
git push origin --delete tag v1.4.0
```

> 删除 Release 后，`releases/latest` 自动回退到上一个可用版本，**应用内升级检测也随之回退**（核心止血机制）。

### 2.2 代码回滚（修复代码库）

```bash
# 方式 A：revert（推荐，保留历史）
git revert v1.4.0 --no-edit
git push origin main

# 方式 B：reset + force push（仅限未发布确认前，且需管理员权限）
git reset --hard v1.3.0 && git push --force origin main
```

> 注意：main 分支已启用保护（PR 审查 + CI），回滚改动请走 **PR 流程**合并，确保 CI 通过后再推送。

### 2.3 重新发布（回滚后）

```bash
python3 scripts/release.py --execute --version 1.4.1   # PATCH 修复版本
```

## 3. 应用层面（用户侧处置）

| 场景 | 用户操作 |
|---|---|
| 新版本启动即崩溃 | 卸载新版本，重新下载上一正式版（GitHub Releases 页） |
| 版本可用但功能异常 | 在旧版本中删除 `media_rename_cache.json` 缓存文件后重启（缓存与版本强绑定，升级/回退会自动重建） |
| 数据安全担忧 | 回滚前先备份 `backups/` 目录（工具内置撤销/重做与备份机制） |

**版本兼容性设计**：
- 缓存文件绑定版本号——升级后旧缓存自动失效重建，回退同理，**不会用新格式读旧缓存**。
- 升级检测仅在**正式 Release** 中生效（prerelease 不触发），避免预发布版被推送给普通用户。

---

## 4. 预发布（防止坏版本直达用户）

正式发布前先走预发布流程，大版本（MINOR/MAJOR）必选：

```bash
# 1) 版本号设为预发布：v1.4.0-rc.1（version.py 仍写 1.4.0）
git tag v1.4.0-rc.1 && git push origin tag v1.4.0-rc.1
# → GitHub Actions 自动构建，创建 prerelease（含双平台产物 + SHA256 校验）
```

- 预发布版**不会**被 `releases/latest` 返回 → 应用内升级检测**不会**提示普通用户
- 测试通过后，正式发布：`python3 scripts/release.py --execute --version 1.4.0`

---

## 5. 回滚演练清单

发布大版本前建议演练一次（约 10 分钟）：

- [ ] 确认上一正式版 Release 存在且产物完整（SHA256 可校验）
- [ ] 确认 `gh release delete` 有权限
- [ ] 确认 main 分支保护下 revert 的 PR 路径可用
- [ ] 确认应用在旧版本下能正常使用（本地保留一份旧版可执行文件）

---

## 6. 事后复盘

回滚完成后记录（docs/reports/ 下）：

1. 故障现象与影响范围（哪个平台、哪种操作触发）
2. 根因（代码、打包、环境还是流程）
3. 修复措施（补丁版本 / 流程改进）
4. 预防措施（测试用例补充、冒烟覆盖、发布检查项）
